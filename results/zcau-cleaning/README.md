# Клининг: ответ за 2 минуты, 0 потерянных заявок

> 📁 В папке — учебный кейс «Автоматизация обработки заявок в сервисной
> компании», [скриншоты](screens.md) и [мини-портфолио](portfolio.md).
> Данные и цифры смоделированы: это демонстрация логики решения, а не отчёт
> о реальном внедрении.

## Контекст и задача

Небольшая сервисная компания (клининг) принимает заявки с сайта и из
мессенджеров. Заявки попадают в почту и общий чат: менеджер видит их не сразу,
часть теряется в часы пик и в выходные, данные вручную переносятся в таблицу.
Клиент ждёт первого ответа 30–60 минут, статус оплаты нигде не связан с записью,
а к концу месяца нет быстрой сводки по обращениям.

Нужно было получить единый реестр заявок, автоматический ответ клиенту со
ссылкой на оплату, уведомление менеджеру и контроль сбоев.

## Что делает сценарий

- принимает заявку из формы и проверяет обязательные поля и сумму;
- разбирает обращение через GigaChat и проверяет, что сумма в ответе совпадает
  с заявкой;
- создаёт запись в NocoDB со статусом «Новая», после сборки ссылки обновляет
  её и меняет статус на «Ожидает оплату»;
- собирает ссылку ЮMoney QuickPay с идентификатором заявки и проверяет её
  HEAD-запросом;
- отправляет клиенту письмо с подтверждением и ссылкой, менеджеру — карточку
  заявки в Telegram;
- при сбое присылает письмо с названием сценария, нодой, текстом ошибки и
  ссылкой на выполнение; раз в день формирует сводку по расписанию.

## Результаты замеров

| Показатель | До | После |
|---|---|---|
| Время первого ответа клиенту | 30–60 мин | 1–2 мин, автоматически |
| Заявок без ответа | 10–15% в загруженные дни | 0 по журналу обработки |
| Ручной перенос в таблицу | 5–6 ч в неделю | около 1 ч (только исключения) |
| Статус оплаты | в переписке | в записи заявки |
| Отчётность | вручную в конце месяца | сводка по расписанию |

Методика: 100 заявок в месяц, около 25 в неделю; ручная обработка одной
заявки — примерно 12 минут (ответ, перенос, ссылка, уведомление). Цифры
оценочные, проверены на 30 тестовых заявках; реальная оплата в демонстрации не
проводилась. Это учебный кейс, а не замеры реального внедрения.

## Стек

n8n (self-hosted, Docker), Form Trigger, GigaChat HTTP API, NocoDB,
ЮMoney QuickPay, Яндекс SMTP, Telegram Bot API, Error Workflow,
Schedule Trigger.
